# WeatherNext 3 — предварительный выпуск RC1

## Добавлено

Общий раздел WN3 для Telegram, MAX и VK: точка, метеограмма PNG/DOCX/PDF, облачность по времени, сравнение трёх вариантов осадков; карты облачности/осадков/T2/разброса T2/ветра 100 м/радиации; PNG, CSV, MP4/H.264 с GIF fallback.

Верхняя атмосфера через GCS/Zarr: профиль, Skew-T и матрица срок × уровень. Использованы существующие визуализаторы; 13 изобарических уровней, средний профиль или отдельный член. Выбираются точка/уровни/часы/члены до загрузки значений. BigQuery остаётся источником поверхностных статистик.

Единый сценарий: город/координаты/геолокация, неоднозначные города, все сроки +1…+360, owner-bound кнопки после перезапуска, защита от повторного запуска, редактируемый статус, отмена, сохранённые сценарии и расписания. Защищённый API возвращает ZIP с теми же результатами. Без API key endpoint выключен.

## Исправлено

Отсутствующий срок не заменяется соседним. Проверяются точные valid/init/lead, дубликаты узлов, единая сетка кадров и согласованность T/Td-квантилей. Кэш имеет атомарную запись, flock и проверку содержимого. Разделены средняя скалярная скорость ветра и направление среднего вектора. BigQuery не выдаётся за реально загруженные 64/64 члена; RH из средних T/Td обозначена как диагностика.

## Проверки

Публикация допускается только после успешных полных unit/contract/render тестов на Python 3.10 и 3.11, runtime/import check и реальных GFS smoke +24/+384, meteorology_live_smoke и meteogram_live_smoke. Новые WN3-тесты проверяют синтетическую BigQuery-схему, настоящий локальный Zarr, PNG/DOCX/PDF, MP4/GIF, общий сценарий и API. Локальный полный набор до проверки совместимости: 542 теста, Python 3.13. Итоговый набор CI дополнительно проверяет отказ GCS на Python 3.10.

**Google WN3 live-доступ, allowlist/ADC/billing, production-чаты и deploy сервера этим выпуском не подтверждены.** Синтетические данные не являются оперативными прогнозами; в архив релиза включён исходный код, а не глобальные модельные данные.

## Ограничения RC

**Полный набор WN3 требует Python 3.11+.** На Python 3.10 поддержаны GFS и поверхностные продукты BigQuery; верхняя атмосфера явно отключена до обновления интерпретатора. Zarr 3 не поддерживает Python 3.10. В CI 3.10 пропущен только файловый Zarr roundtrip, на 3.11 этот тест обязателен.

WN3-маршруты, вертикальная скорость, вероятности событий по всем членам и сравнение циклов ещё не реализованы. Квантили поверхности не используются для выдумывания точных вероятностей. В профилях 13 уровней, уровни ниже рельефа не маскированы; диагностика среднего профиля не равна средней диагностике ансамбля и не является сертифицированной авиационной продукцией.

Периоды метеограммы считаются от фактического init, а не от текущей минуты. Telegram WN3 использует common SQLite/scheduler; прежние GFS-расписания сохранены отдельно и их лимит учитывается отдельно. Для WN3 автоматической отправки нужен общий production runtime.

## Включение

См. `docs/WEATHERNEXT3.md` и `.env.telegram.example`. Нужны allowlisted ADC от имени systemd-пользователя, BigQuery linked project/dataset и billing project для Requester Pays GCS. По умолчанию лимит BigQuery — 1 GB на отдельный запрос, не суммарный бюджет; для GCS установлены отдельные пределы выбранных данных/чанка/оценки чтения. Ключи хранить вне checkout.

`python weathernext3_check.py` проверяет конфигурацию без облачного запроса. `--live` проверяет BigQuery, `--live --upper` — GCS; эти операции могут тарифицироваться. Выпуск не меняет main и не равнозначен обновлению `/opt/gfs_profile`: на сервере требуется обычный deploy рабочей ветки.
