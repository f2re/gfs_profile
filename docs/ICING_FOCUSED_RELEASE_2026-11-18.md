# Обледенение: крупнее карта, свободное поле и проверенное меню

Дата проверки: 18 ноября 2026 года. Рабочая ветка: `telegram-bot`, целевая — `main`.
Продолжение [первой проверки интерфейса](ICING_UX_ACCEPTANCE_2026-11-18.md).

## Карта и выбранный пункт

Новый стандартный район — **12–85° в.д., 40,5–70,5° с.ш.** Он охватывает
Берлин — Новосибирск и южный берег Чёрного моря — Кольский полуостров с небольшим
запасом по краям. Проекция Ламберта автоматически центрируется на 48,5° в.д.,
55,5° с.ш. Линейный масштаб около Москвы увеличен примерно в 1,66 раза
относительно предыдущего стандартного района при той же ширине изображения.

Большая плашка выбранного пункта, текст над ней и выноска удалены. На поле
остаётся небольшой оранжевый кружок с белой обводкой; координаты находятся
в нижней строке рядом с источником. Маркер целиком виден в углах района, его
центр точно соответствует координатам. Он остаётся виден и поверх сообщения
о пустом или неопределённом поле.

Моря, озёра и реки выделены голубым. Подписи городов размещаются по приоритету
с проверкой пересечений; на проверенных изображениях нового района помещаются
52 города. Берлин, Мурманск и Новосибирск видны с полными подписями.
Городские подписи и изолинии учитывают положение выбранного пункта.

Прежнее значение шаблона `ICING_BBOX=-15,100,34,80` при чтении настроек
автоматически означает новый стандартный район. Сохранённый `.env` не меняется.
Другие пользовательские значения сохраняются; явный `bbox=-15,100,34,80`
в команде и район из прежней callback-кнопки продолжают использовать широкий
охват. Тест проверяет оба пути и отсутствие изменений переменной окружения.

## Общее меню Telegram, MAX и VK

Подписи вынесены в небольшой общий каталог `messenger/icing_labels.py`:

| Действие | Подпись |
| --- | --- |
| Построение | ▶ Построить |
| Выбор срока | 🕒 Срок |
| Отметка пункта | 📍 Пункт на карте |
| Пояснения | ℹ Как читать карту |
| Полный файл | ⬇ PNG целиком |
| Новый цикл | ↻ Обновить данные |
| Возврат | ← Назад |
| Отмена | ✕ Отмена |

Выбранные срок, уровень и шаг изолиний отмечены ✓. В строке максимум две кнопки
действий или три коротких числовых значения. После отмены проверки данных или
расчёта остаётся кнопка «Меню». Время инициализации, заблаговременность и дата/час
действия прогноза показываются явно, в UTC.

Нативная Telegram-клавиатура геолокации определяет возврат/удаление по action
и scope, затем использует общий каталог подписей. Прежние текстовые кнопки
также принимаются. Формат callback, ограничение 64 байта и проверка владельца
не изменены.

Сквозной тест через `ScheduleMessengerRouter` выполняет для каждой платформы:
открытие → справка → выбор неоднозначного города → геолокация → страницы сроков
до +384 → построение → оригинал PNG → возврат/меню. Проверяется сохранение
цикла, пункта, района и выбранных параметров. Отдельно проверены статус/отмена
на трёх платформах и текущие/прежние подписи нативных кнопок Telegram.
Это проверки общего flow и адаптеров с тестовыми gateway; они не отправляют
сообщения в действующие чаты.

## Проверка на GFS

Обе обязательные команды завершились успешно:

```bash
python -m gfs_core --lat 45.0355 --lon 38.9753 --lead 24
python -m gfs_core --lat 55.75 --lon 37.62 --lead 384
```

В этой проверке оба срока доступны у цикла **18.11.2026 12 UTC**.
Время действия +24 — **19.11.2026 12 UTC**, +384 — **04.12.2026 12 UTC**.
Проверяется публикация нужного срока, а не только `f000`.

Для нового района выполнена свежая загрузка региональных GRIB через NOMADS,
строгое чтение, расчёт и построение двух продуктов: `godske_sum` и `slw_max`.
Цикл **18.11.2026 12 UTC**, +24; сетка **121 × 293 = 35 453 узла**,
17 изобарических уровней. Результаты содержат только PNG, без CSV. Проверены
дата/час, источники, декаметры для мощности, маркер, города и отсутствие плашки.

Пять вариантов компоновки дополнительно просмотрены на точной вырезке той же
сетки из ранее проверенного широкого GRIB: максимум воды, мощность по Годске,
сравнение методов, пункт на границе и карта без пункта. Эти просмотры не
использовали новые сетевые запросы. Пиксельные тесты подтверждают видимость
маркера во всех четырёх углах и на пустом поле.

Итоговый `python -m unittest discover -s tests`: **776 тестов за 58,041 с**,
774 прошли, 2 пропущены из-за необязательных зависимостей WeatherNext 3
(`google.cloud.bigquery`, `zarr`). Ошибок и падений нет. `git diff --check` чистый.
Независимый просмотр diff проверил миграцию района, callback owner/scope,
совместимость кнопок и положение маркера; найденное перекрытие маркера сообщением
о пустом поле исправлено и покрыто отдельным регрессионным тестом.

Численные алгоритмы обледенения не менялись. Этот протокол подтверждает
работу программы и компоновку, а не прогностическое качество диагностики.
Перезапуск рабочего сервера и доставка в действующие чаты здесь не подтверждены.
