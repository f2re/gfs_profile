# 📊 Метеограмма Telegram-бота

## Назначение

`/meteogram` строит временной модельный прогноз по одной точке. Продукт не заменяет `/windgram`: windgram показывает вертикальную структуру по уровням давления, а meteogram — приземные параметры по времени.

Рендер и терминология синхронизированы с проверенной реализацией `f2re/weather-to-docx` на уровне нормализации полей, смысловых шкал и компоновки. DOCX-специфические ограничения страниц и LibreOffice в Telegram-бот не перенесены.

## Источники

Модель всегда задаётся явно. `best_match`, скрытый переход на другую модель и межмодельный «суперансамбль» запрещены.

Детерминированные модели:

- GFS 0.25° · NOAA/NCEP;
- ECMWF IFS 0.25° Open Data;
- ECMWF AIFS 0.25° Single;
- DWD ICON Global;
- ECCC GEM Global/GDPS.

Ансамбли:

- GEFS 0.25° · NOAA/NCEP, 31 член;
- ECMWF IFS ENS, 51 член;
- ECMWF AIFS ENS, 51 член;
- DWD ICON Global EPS, 40 членов;
- ECCC GEPS, 21 член.

Доставка выполняется через Open-Meteo. На PNG и в Telegram-caption сохраняются исходная модель, центр и канал доставки.

## Контроль входных данных

Перед построением проверяются:

- наличие минимум двух сроков температуры;
- строго возрастающая временная шкала;
- единицы температуры, влажности, осадков, давления и ветра;
- наличие отдельных членов ансамбля;
- фактическое число членов по каждому сроку;
- повреждённый или просроченный кэш.

Неожиданная единица измерения считается ошибкой. Отсутствующая единица фиксируется предупреждением, но не подменяется скрытым пересчётом.

## Временная шкала и цикл

Запрос выполняется с `timezone=auto`. На оси используется местное время точки. Длительности интервалов считаются по фактически прошедшему времени UTC, а повторяющийся местный час при переходе на зимнее время разрешается по `fold`, поэтому сезонный перевод часов не искажает порядок сроков и интенсивность осадков. Время получения и генерации показывается в UTC.

Стандартная выдача Open-Meteo не содержит надёжного времени исходного цикла. Бот не угадывает цикл и пишет:

```text
цикл не передан поставщиком
```

## Панели и смысловые шкалы

Пять панелей:

1. низкая, средняя и высокая облачность;
2. температура и точка росы;
3. относительная влажность;
4. интенсивность осадков, суточные суммы и ансамблевые вероятности;
5. ветер, порывы, направление и давление.

Непрерывные поля сглаживаются PCHIP только для отображения. Осадки и вероятности не сглаживаются.

Температурная шкала не уже `−20…+40 °C` и расширяется шагом 5 °C. Выделены физически значимые зоны и переходы через 0 °C.

Влажность всегда показана на шкале `0…100 %`. Диагностическая подпись тумана выводится только при коде тумана либо сочетании высокой влажности, малого дефицита точки росы и слабого ветра.

Шкала ветра не уже `0…25 м/с`. Средний ветер и порывы классифицируются раздельно:

```text
сильный ветер   средняя скорость ≥10 м/с
сильные порывы  порывы ≥14 м/с
опасные порывы  порывы ≥20 м/с
```

Давление использует диапазон не уже `970…1040 гПа` и справочную линию 1013 гПа.

## Осадки

Сумма за интервал переводится в эквивалентную интенсивность:

```text
мм/ч = сумма за интервал / длительность интервала
```

Для всех моделей используется единая шкала:

```text
0,5 · 2 · 5 · 10 · верхняя граница 12 мм/ч
```

Значение выше 12 мм/ч визуально ограничивается, но фактическая интенсивность подписывается стрелкой. Следовые осадки менее 0,1 мм/ч показаны коротким маркером у нулевой линии, а не искусственно увеличенным столбиком.

Обычные столбики не имеют чёрной обводки. Цвет столбика определяется только числовой интенсивностью: код грозы или ливневого характера не повышает слабые осадки до класса «ливень». В детерминированном прогнозе фиолетовая обводка отдельно отмечает грозовой срок; модальный код ансамбля не используется для категоричного суточного утверждения о грозе или фазе осадков.

Для местных суток выводится одна компактная характеристика из тех же числовых данных:

```text
3,0 мм/сут · снег
5,7 мм/сут · заметные осадки
11,2 мм/сут · гроза
1,2 мм за 12 ч · небольшие осадки
```

Сухие сутки не получают повторяющуюся подпись. Сумма с отметкой ровно `00:00` относится к предшествующему интервалу и предыдущим местным суткам. Подпись `мм/сут` используется только при полном покрытии местных суток; для неполного окна выводится `мм за N ч`. Фаза осадков определяется отдельно; снег не называется дождём.

## Ансамблевая статистика

Разные ансамблевые системы не смешиваются. Внутри одной системы члены равновероятны.

- температура, точка росы и давление: центр — среднее;
- осадки, влажность, облачность, ветер и порывы: центр — медиана;
- внутренняя полоса: q25–q75;
- внешняя полоса: q10–q90;
- направление ветра: круговое среднее;
- вероятности осадков: сырые доли членов для порогов 0,1, 1 и 5 мм за исходный интервал;
- суточные осадки: медиана сумм, сначала накопленных отдельно для каждого члена;
- низкая, средняя и высокая облачность запрашиваются и показываются раздельно;
- средняя точка росы показывается вместе со средней температурой.

Квантили рассчитываются методом Hyndman–Fan type 8 (`numpy method=median_unbiased`). Отсутствующие члены не заменяются нулями. На изображении и в сообщении показываются фактическое и ожидаемое число членов, а при выпадении данных — минимальное число членов на отдельных сроках; неполный ансамбль явно маркируется.

## Компоновка

- заголовок, модель, поставщик, период и служебные данные разнесены по независимым строкам;
- легенды вынесены над панелями и имеют непрозрачный белый фон;
- суточные подписи осадков находятся в отдельной строке ниже легенды;
- фоновые категории температуры и влажности вынесены в правое свободное поле;
- количество стрелок ветра и часовых подписей уменьшается для длинных периодов;
- пользовательские аннотации проходят bounding-box контроль после финального layout-pass, при этом легенды считаются неперекрываемыми областями;
- обычные столбики осадков не имеют видимого края;
- шрифт стрелок ветра явно задан как DejaVu Sans;
- PNG проверяется на ограничения Telegram Photo и при необходимости отправляется документом.

Регрессионные тесты отдельно проверяют, что легенда осадков не перекрывает суточные подписи.

## Зависимости

Новых библиотек для `/meteogram` не добавлено. Используются уже закреплённые зависимости проекта:

```text
numpy==2.2.6
requests==2.32.3
matplotlib>=3.8,<4
scipy>=1.13
Pillow>=10,<12
python-telegram-bot>=22,<23
```

`scipy` используется для PCHIP, `requests` — для синхронного HTTP внутри `asyncio.to_thread`, Pillow — для проверки и безопасной отправки PNG. Установщик ставит DejaVu Fonts. `runtime_check.py` импортирует все meteogram-модули после принудительного выбора backend `Agg`.

После установки рекомендуется:

```bash
/opt/gfs_profile/.venv/bin/python -m pip check
/opt/gfs_profile/.venv/bin/python /opt/gfs_profile/runtime_check.py
```

## Кэш и ограничения

Ответы кэшируются в:

```text
.cache_gfs/meteogram
```

Ключ включает модель, координаты, параметры и период. По умолчанию TTL — 3 часа. Повреждённый кэш удаляется. Deploy сохраняет весь `.cache_gfs`.

Переменные:

```env
MAX_CONCURRENT_METEOGRAM=2
METEOGRAM_CACHE_TTL=10800
METEOGRAM_HTTP_TIMEOUT=90
METEOGRAM_HTTP_RETRIES=3
METEOGRAM_DPI=170
```
