# 📊 Метеограмма Telegram-бота

## Назначение

`/meteogram` строит полноценный временной прогноз по одной точке. Продукт не заменяет `/windgram`: windgram показывает вертикальную структуру по уровням давления, а meteogram — приземный прогноз по времени.

## Источники

Модель всегда задаётся явно. Сервис `best_match` и скрытый переход на другую модель запрещены.

Детерминированные модели:

- NOAA GFS 0.25°;
- ECMWF IFS 0.25° Open Data;
- ECMWF AIFS 0.25° Single;
- DWD ICON Global;
- ECCC GEM Global/GDPS.

Ансамбли:

- NOAA GEFS 0.25°, 31 член;
- ECMWF IFS ENS, 51 член;
- ECMWF AIFS ENS, 51 член;
- DWD ICON Global EPS, 40 членов;
- ECCC GEPS, 21 член.

Доставка выполняется через Open-Meteo. Название исходной модели и центра сохраняется на PNG и в Telegram-caption.

## Временная шкала и цикл

Запрос выполняется с `timezone=auto`. На оси используется местное время точки. Время получения и генерации показывается в UTC.

Стандартная выдача Open-Meteo не содержит надёжного времени исходного цикла. Бот не угадывает цикл и пишет:

```text
цикл не передан поставщиком
```

## Параметры

Пять панелей:

1. низкая, средняя и высокая облачность;
2. температура и точка росы;
3. относительная влажность;
4. осадки, суточные суммы и ансамблевая вероятность;
5. ветер, порывы, направление и давление.

Сумма осадков за интервал переводится в интенсивность:

```text
мм/ч = сумма за интервал / длительность интервала
```

Осадки не сглаживаются. Температура, точка росы, влажность, облачность, ветер и давление сглаживаются PCHIP только для отображения.

## Ансамблевая статистика

Разные ансамблевые системы не смешиваются. Внутри одной системы члены равновероятны.

- температура, точка росы и давление: центр — среднее;
- осадки, влажность, облачность, ветер и порывы: центр — медиана;
- внутренняя полоса: q25–q75;
- внешняя полоса: q10–q90;
- направление ветра: круговое среднее;
- вероятности осадков: сырые доли членов для порогов 0.1, 1 и 5 мм за интервал.

Квантили рассчитываются методом Hyndman–Fan type 8 (`numpy method=median_unbiased`). Отсутствующие члены не заменяются нулями.

## Компоновка и предотвращение пересечений

- заголовок, период и служебные данные разнесены по независимым строкам;
- легенды располагаются в непрозрачных белых блоках;
- надписи осадков: максимум один пик и одна сумма на сутки;
- температура подписывает только глобальный минимум и максимум;
- число стрелок ветра автоматически уменьшается для длинного периода;
- для 10–15 суток уменьшается частота часовых подписей;
- ночные интервалы рассчитываются по положению Солнца, если источник не передал `is_day`;
- пользовательские аннотации проверяются по bounding box после layout-pass; подпись меньшего приоритета скрывается при конфликте.

Тесты строят детерминированные и ансамблевые PNG, включая длинный 15-суточный период и длинное название пункта.

## Кэш и ограничения

Ответы кэшируются в:

```text
.cache_gfs/meteogram
```

Ключ включает модель, координаты и период. По умолчанию TTL — 3 часа. Deploy сохраняет весь `.cache_gfs`.

Переменные:

```env
MAX_CONCURRENT_METEOGRAM=2
METEOGRAM_CACHE_TTL=10800
METEOGRAM_HTTP_TIMEOUT=90
METEOGRAM_HTTP_RETRIES=3
```

## Проверка

```bash
python -m unittest tests.test_meteogram -v
python -m unittest discover -s tests
```

Telegram smoke:

```text
/meteogram
Москва
Одна модель → ECMWF IFS → 5 суток → Построить
Ансамбль → GEFS → 10 суток → Построить
/meteogram Москва source=gfs days=5
/meteogram Москва ensemble=ecmwf days=5
```
