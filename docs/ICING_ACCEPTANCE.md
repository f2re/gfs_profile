# Приёмка раздела «Обледенение»

Дата: 18 ноября 2026 года. Ветка: `telegram-bot`.

## Область приёмки

Проверены 10 картографических представлений GFS и общий сценарий `/icing`
для Telegram, MAX и VK: регион без ввода города, продукт, срок, уровень,
изолинии, построение, PNG/CSV, статус и отмена. Методика и границы выпуска:
[ICING_MAPS_SPEC.md](specs/ICING_MAPS_SPEC.md).

Продукты WAFS, диагностика переохлаждённых осадков, длительность, анимация и
маршрутный разрез обледенения не входят в этот выпуск и не показаны как готовые.

## Численная и контрактная проверка

```bash
.venv/bin/python -m unittest discover -s tests -p 'test_*icing*.py' -v
```

Результат независимого прогона: **60 проверок, OK**. После добавления проверки
повторной загрузки/HTML ведущий разработчик подтвердил итоговый focused-набор:
**61 проверка, OK**; тесты GFS/обледенения не пропущены.

| Группа | Что подтверждено |
|---|---|
| Запрос и источник | Валидация области и параметров; индекс требуемого срока; полный состав полей; переход к предыдущему циклу; отсутствие скрытой подмены явно выбранного цикла |
| GRIB и кэш | Тип уровня, единицы, время и сетка; HTML/оборванный GRIB отклоняются; повреждение packed data обнаруживается по сохранённой контрольной сумме |
| Геометрия | Несколько слоёв, инверсии, пересечения внутри интервала, отсутствие мостиков через пропуск, строгая граница T < 0, рельеф и незамкнутые границы |
| Вода | Отдельная пригодность полей воды и Td; холодная часть интеграла; нулевой максимум без выдуманной высоты; неизвестное значение не заменяется нулём |
| Физические инварианты | Изменение CLWMR не меняет геометрию Годске; гидростатический SLWP имеет смысл массы на площадь; отсутствие CLWMR не уничтожает пригодную термодинамическую диагностику |
| Экспорт | Фактические run/valid, единицы и версия метода; раздельные признаки первого слоя и общего столба; названия категорий сравнения; независимые временные файлы параллельных запросов |
| Меню | Общий набор продуктов для трёх платформ, вход из `/start` и меню карты, отсутствие запроса города, полная пагинация сроков до +384 |
| Callback | Полный запрос восстанавливается после нового экземпляра router; размер укладывается в 64 байта; привязка к платформе/пользователю/чату |
| Жизненный цикл | Раннее подтверждение callback; общий лимит GFS сохраняется до выхода рабочего потока после отмены; отменённый результат не отправляется; частичные файлы удаляются |
| Telegram | Регистрация действительного Application, тонкий адаптер к common router, выход из мастера, `/status`/`/cancel`, оригинальный PNG как документ |

Идеализированные столбцы в unit-тестах проверяют вычисления и не выдаются за
метеорологические наблюдения или реальные случаи.

## Реальный региональный случай

Использованы сохранённые исходные GRIB2 GFS 0,25°:

- цикл **17.11.2026 06 UTC**;
- прогноз **+24 ч**, действителен **18.11.2026 06 UTC**;
- район −15…100° долготы, 34–80° с.ш.;
- **185 × 461 = 85 285 узлов**, 17 уровней 1000–300 гПа;
- исходный исследовательский набор содержит 87 GRIB-сообщений, включая RH,
  которая не требуется для рабочего расчёта Td через SPFH.

Независимый приёмщик декодировал исходные сообщения отдельно от нового IO и
сравнил **14 основных полей** текущего численного ядра с архивным результатом
предварительно верифицированного исследовательского алгоритма. Сверены Td,
водность над рельефом, HΣ, Hmax, границы, число слоёв, признаки открытых границ и
пропусков, SLWP, максимум водности и его высота/давление. Значения совпали:
максимальное абсолютное расхождение **0**. Маска подземных значений LWC применена
к обоим результатам одинаково.

В новом сравнении методов получено:

| Категория | Число узлов |
|---|---:|
| Оба признака отсутствуют | 41 467 |
| Только Годске | 16 146 |
| Только модельная вода | 3 711 |
| Есть пересечение слоёв | 21 761 |
| Оба признака есть в разных слоях | 2 192 |
| Недостаточно сопоставимых данных | 8 |

Пятая категория необходима: совпадение признаков в столбце не означает их
пересечения на одной высоте. Количество узлов в этой таблице относится к одному
модельному случаю и не является частотой или вероятностью обледенения.

## Проверка изображений и замечания

Визуально просмотрены все 10 региональных PNG: вода на уровне, HΣ, Hmax,
основание, верх и число слоёв, максимальная водность, её высота, SLWP и
сравнение методов. Заголовки, единицы, цветовые шкалы, цикл/срок действия и
примечания расположены раздельно и читаемы. Подложка и подписи городов локальные;
рендер не требует Cartopy или сетевых тайлов.

Приёмка выявила и передала на исправление:

1. Дублирующиеся версии метода в config и метеоядре — сведены к одному источнику.
2. Общий признак открытой верхней границы мог неоднозначно трактоваться в CSV
   первого слоя — добавлены `column_lower_open`, `column_upper_open`,
   `first_base_open`, `first_top_open` и самостоятельные названия категорий.
3. Одна сигнатура GRIB не выявляет изменение packed data — при наличии manifest
   проверяются сохранённые размер и SHA-256.
4. Заливка озёр поверх метеополя изменяла соответствие цвета легенде — водоёмы
   перенесены под данные, контуры оставлены поверх.
5. Отрицательные геопотенциальные высоты, обрезание крайних координат и подписи
   максимумов — допустимые отрицательные высоты сохранены, шкала расширена до
   −500 гп.м, подписи у границы рамки исключены, для уровневых продуктов воды
   явно указаны исходные изобарические уровни. Серая маска карты воды на уровне
   подписана «Уровень под рельефом / нет данных».

Все 10 PNG перерисованы после исправлений. Заключительный независимый просмотр
изменённых мест выполнен на `godske_base`, `slw_level`, `slw_max`, `agreement`:
цвета над водоёмами соответствуют легенде, отрицательная часть шкалы видна,
крайние координаты не обрезаны, подписи метода и масок читаемы. Проверка
изображений пройдена; незакрытых блокирующих замечаний не осталось.

## Границы заключения

Эта приёмка подтверждает перенос расчётной методики, вычислительные свойства,
контракты меню и транспорта. Она **не является верификацией прогноза по
наблюдавшемуся обледенению воздушных судов** и не подтверждает калиброванную
интенсивность либо вероятность.

Контракты проверены с тестовыми gateway. Доставку в действующие аккаунты
Telegram/MAX/VK и развёртывание на сервере этот прогон не подтверждает.

## Живые smoke и общий набор тестов

Ведущий разработчик подтвердил выполнение обязательных команд с кодом выхода 0:

```bash
python -m gfs_core --lat 45.0355 --lon 38.9753 --lead 24
python -m gfs_core --lat 55.75 --lon 37.62 --lead 384
```

Первый запрос выбрал цикл **18.11.2026 00 UTC**, valid **19.11.2026 00 UTC**.
Второй выбрал опубликованный для дальнего срока цикл **17.11.2026 18 UTC**,
valid **03.12.2026 18 UTC**. Таким образом, проверка +384 не ограничивалась
готовностью текущего `f000`.

Полная новая цепочка `build_icing_product_result(IcingRequest(product='slwp'))`
прошла с живым NOMADS: цикл **18.11.2026 00 UTC**, +24 ч, **85 285 узлов**,
два региональных GRIB2, PNG и CSV. Зафиксированное время контрольного запроса
**24,01 с**, включая загрузку. Это время одного запуска, не гарантия задержки
сервиса.

Первый общий прогон выявил старое ожидание списка `/health` после добавления
`icing` и два теста опциональных SDK WeatherNext: Google BigQuery и Zarr.
Ожидание обновлено, для интеграционных тестов необязательных SDK добавлен явный
пропуск при отсутствии соответствующего пакета. Это не отключение тестов GFS
или обледенения и не установка Google/Zarr в базовое production-окружение с
выключенным WeatherNext.

Повторный полный прогон с базовым `requirements.txt`:

```text
Ran 629 tests in 43.532s
OK (skipped=2)
```

Пропущены только `test_bigquery_budget_default_and_timeout_cancel` и
`test_real_zarr_roundtrip_and_cache`: требуются опциональные SDK WeatherNext.
GFS, обледенение и их интерфейсные проверки выполнены без пропусков.

Финальный diff и commit/push фиксируются ведущим разработчиком после приёмки.
Развёртывание на внешнем сервере не следует из прохождения локальных проверок.

## Решение независимой приёмки

**Принято для фиксации в ветке `telegram-bot` как расчётная диагностика GFS.**
Блокирующих дефектов в проверенной области не осталось.

| Критерий | Результат |
|---|---|
| Общий use-case и паритет меню Telegram/MAX/VK | Пройдено: общий router/service, тонкий Telegram adapter, контрактные проверки |
| Численная реализация и перенос проверенного случая | Пройдено: инварианты, граничные случаи, 14 полей без расхождений |
| Источник, фактический цикл и пригодность кэша | Пройдено: exact-lead/field coverage, строгий GRIB, контроль SHA-256, живой NOMADS |
| Изображения, CSV и явные ограничения продукта | Пройдено: все 10 PNG, повторный просмотр исправлений, научные признаки в CSV |
| Регрессия базового окружения | Пройдено: 629 тестов, только два обоснованных пропуска опциональных SDK |
| Обязательные живые smoke +24/+384 | Пройдено: обе команды завершились с кодом 0 |
| Доставка в действующие чаты и внешний deploy | Не выполнялись в рамках этой приёмки; локальная готовность их не подтверждает |
| Верификация прогноза по фактическому обледенению | Не выполнена; продукт не объявлен калиброванной вероятностью или интенсивностью |
