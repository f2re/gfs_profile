# Меню и подписи: приёмка обновления

Дата: 18 ноября 2026 года.

## Результат

Главное меню Telegram, MAX и VK использует общий каталог продуктов. Основные
экраны содержат короткую подпись `GFS data`, выбранные параметры и действия.
Названия, порядок продуктов и правила раскладки определены в
[`messenger/menu_catalog.py`](../messenger/menu_catalog.py). Длинные названия
занимают всю строку; в остальных строках размещаются до двух действий или до
трёх коротких числовых вариантов.

| Раздел | Команда | Содержимое |
|---|---|---|
| Профиль | `/profile` | Точка, срок, вертикальный профиль, PNG/CSV |
| Аэрограмма | `/aero` | Точка, срок, Skew-T, годограф и показатели |
| Высота × срок | `/windgram` | Ветер, температура или влажность; период и шаг |
| Облака | `/cloudgram` | Облака, осадки, явления; краткий и подробный вид |
| Карта | `/map` | Одна карта, серия, анимация; район и подложка |
| Метеограмма | `/meteogram` | Источник, период, обычный/ансамблевый прогноз, PNG/DOCX/PDF |
| Обледенение | `/icing` | Десять карт по выбранному району, срок, уровень, изолинии, PNG/CSV |
| Маршрут | `/route` | Начало/конец, вылет, скорость, шаг, краткий/подробный разрез |
| Настройки | `/settings` | Основная точка и сохранённые сценарии |
| Расписания | `/schedule` | Создание, просмотр, запуск и удаление отправок |
| Справка | `/help` | Краткие примеры и команды |

WeatherNext 3 остаётся выключенным по умолчанию. При явном включении появляются
его кнопка и строка `/wn3` в справке. Другие источники в метеограммах и экспортах
сохраняют собственные названия.

## Исправленные переходы

1. В полном общем роутере `/profile` мог попадать в метод запроса точки карты
   с другой сигнатурой. Метод карты получил отдельное имя, оба пути проверены
   через production-класс `ScheduleMessengerRouter`.
2. Telegram показывал главное меню, сохраняя прежний мастер. Теперь возврат
   и открытие следующего продукта очищают незавершённый выбор. Прямой `/route`
   после `/meteogram` также начинает один новый сценарий.
3. В персональном профиле добавлены `+3` и пагинация всех сроков до `+384`.
   Выбранная точка сохраняется при переходах между страницами.
4. Создание расписания после потери состояния больше не заканчивается
   молчаливым нажатием: открывается список расписаний с предложением начать
   создание заново.
5. «Меню» и «Справка» доступны из старого состояния выключенного WeatherNext
   с первого нажатия. Непосредственный запрос выключенного источника остаётся
   заблокированным.
6. Общие кнопки возврата переводятся в собственные Telegram callbacks.
   Старые продуктовые payload сохранены.
7. Выход в меню во время построения обледенения сохраняет фоновую задачу;
   результат доставляется после завершения. Отмена выполняется отдельным
   действием.

## Подписи и графика

Повторяющиеся «не наблюдение», «не радиозонд», «не радар» убраны из основных
экранов и результатов. Время выпуска и действия, координаты, узел, единицы,
пропущенные данные и признаки качества сохранены. Определения диагностик
находятся в [методиках](METEOROLOGICAL_METHODS.md); для обледенения есть
отдельная кнопка «О методах».

- Карты обледенения: крупнее заголовки, шкала, подписи изолиний и городов;
  подвал содержит короткую легенду, время и район. Мощность обозначена в гп.м,
  границы и незамкнутые слои имеют прежний смысл.
- Windgram: даты вынесены в отдельную строку сетки; заголовок и даты не
  перекрываются. Значение каждой ячейки рисуется одним текстовым объектом.
- Cloudgram: увеличены подписи и значения, убраны повторные полупрозрачные
  даты поверх данных. Для неизвестного интервала осадков нет пустого «— ч».
- Профиль: сводка вынесена из области ветровых значений, давление и высота
  в метках оси располагаются в одну строку.
- Метеограмма: крупнее оси и легенды, компактнее подвал. Если источник
  сообщает время инициализации, шапка показывает этот цикл.
- Композитная карта: три содержательные строки легенды, без перечня GRIB-полей
  и счётчиков объектов подложки на изображении.
- Маршрут: все исходные группы участков сохранены; сводка расположена в
  равномерной сетке до пяти карточек в строке. Короткий последний участок
  больше не сжимает надписи. Локальный пик вынесен в заголовок карточки.

Численные алгоритмы GFS, пороги диагностик, границы групп маршрута и оценка
риска в этом обновлении не изменены.

## Очистка кода

- Один обработчик главного меню вместо одиннадцати реализаций `_start`.
- Общий каталог вместо отдельных списков главного меню и расписаний.
- Удалён `telegram_result_copy.py`; короткие подписи формируются сразу в
  исходных formatter-функциях.
- Удалены повторные подмены captions и текстов домашнего экрана.
- Удалены неиспользуемые варианты рисования маршрутных карточек и связанная
  с ними подмена функций при импорте. Используется одна действующая политика
  карточек для обоих видов разреза.
- В windgram устранён второй идентичный текстовый объект в каждой ячейке.

## Проверки

Проверки меню выполнялись через полный общий роутер и фактические группы
обработчиков собранного `telegram_bot.build_application()`. Транспорт и
построение в сценарных тестах заменены тестовыми объектами; реальным
пользователям сообщения не отправлялись.

| Проверка | Подтверждение |
|---|---|
| Полный набор `unittest discover -s tests` | 700 тестов за 54,203 с; `OK (skipped=2)`, exit 0 |
| Восемь продуктов × три платформы, 24 сквозных прохода | `test_messenger_menu_walkthrough.py`: старт → выбор → точка/параметры → результат → меню |
| Все страницы сроков до `+384`, подменю, возврат и отмена | Общие walkthrough и профильные router-тесты |
| Итоговая Telegram-цепочка, старые мастера, WN3 guard, пагинация | `test_telegram_menu_navigation.py` и профильные flow-тесты |
| Подписи и положение элементов графиков | `test_product_readability.py`, `test_route_card_readability.py` |
| Карточки маршрута с двумя факторами и локальным пиком | Геометрическая проверка текста в обоих видах разреза; сохранены все десять групп |
| Загрузка GFS +24 | Краснодар: цикл `20261118/12`, valid `2026-11-19 12:00 UTC`, exit 0 |
| Загрузка GFS +384 | Москва: цикл `20261118/06`, valid `2026-12-04 06:00 UTC`, exit 0 |
| Runtime import check | Успешен после удаления устаревшего модуля |
| Визуальный просмотр | 13 PNG: профиль, аэрограмма, windgram, два cloudgram, две метеограммы, карта, три icing, два маршрута |

Два пропуска относятся к необязательным провайдерам BigQuery/Zarr без их SDK
в локальном окружении. Обязательные тесты меню, расчётов и deploy прошли.

Три карты icing для визуальной проверки построены из реальных ранее загруженных
GRIB `20261118/00 f024`; остальные PNG — воспроизводимые контрольные наборы.
Маршрутные карточки и найденные наложения повторно просмотрены после исправлений.

Два теста категорий маршрута при изолированном запуске зависели от порядка
импортов. Та же ошибка воспроизведена на чистом исходном commit `58f331b`.
В тестовой подготовке теперь явно включается существующая production-политика,
как в соседнем наборе; ожидания категорий и сами формулы сохранены.

## Выпуск

Изменения разрабатываются в `telegram-bot` и выпускаются в `main` после
полного набора тестов и GitHub Actions. Установленный автообновлятор берёт
`main`, выполняет проверки готовности и синхронизирует native-команды.
Новый `/start` формирует обновлённые кнопки из общего каталога. Старые сообщения
в истории сохраняют прежний вид, их поддерживаемые callbacks работают.

Порядок серверной проверки: [DEPLOY.md](../DEPLOY.md). Публикация в GitHub
и успешные CI-проверки подтверждают выпуск исходников; состояние работающего
systemd и доставку в живые чаты необходимо подтверждать на сервере.

Официальная схема клавиатуры MAX сверена с
[документацией клавиатуры](https://dev.max.ru/docs-api/use-cases/sending-messages/keyboard/)
и [историей API](https://dev.max.ru/docs-api/changelog-api) 18.11.2026.
