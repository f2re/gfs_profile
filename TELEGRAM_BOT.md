# 🤖 Telegram-бот GFS

Бот строит модельные вертикальные, временные и картографические продукты GFS 0.25° по городу, координатам или Telegram-геолокации.

Это модельная сетка GFS, не радиозонд, не метеостанция и не наблюдение.

## Что возвращает

- температура, точка росы и относительная влажность;
- ветер: направление, скорость, U/V-компоненты;
- изотермы 0/-10/-20 °C;
- PNG и CSV;
- `/route` — вертикальный разрез вдоль маршрута до 500 гПа;
- `/map` — одна PNG-карта, серия PNG или MP4-анимация.

## Основные команды

```text
/start      старт и геолокация
/help       инструкция
/cancel     сброс выбора
/cycle      последний опубликованный анализ GFS
/status     доступность сроков и состояние кэша
/profile    вертикальный профиль по точке
/route      вертикальный профиль по маршруту
/aero       аэрологическая диаграмма
/skewt      быстрая Skew-T
/windgram   срок × уровень
/cloudgram  облачность, осадки, грозы
/map        карта, серия PNG или MP4-анимация
/admin      статистика и отчёты
```

Примеры:

```text
/profile Москва +24
/profile Москва run=20260630/06 +24
/route Москва -> Санкт-Петербург +24 speed=300 mode=pro
/route 55.75 37.62 -> 59.94 30.31 +6 speed=450 mode=simple
/map Москва from=0 to=24 step=3 mode=gif
```

## Сроки GFS

На первой странице показаны популярные сроки:

```text
+0, +3, +6, +12, +24, +48 ч
```

Полный диапазон:

```text
0..120 ч — каждый час
123..384 ч — каждые 3 часа
```

## Progress

Для долгих операций бот обновляет одно статусное сообщение:

```text
1/5 Проверяю публикацию forecast-файла
2/5 Привязываю точку к узлу GFS
3/5 Скачиваю GRIB2
4/5 Читаю xarray/cfgrib/eccodes
5/5 Формирую сводку, PNG и CSV
```

Для `/route` дополнительно показывается номер расчётной точки, расстояние и ETA-срок.

## Маршрутный профиль `/route`

### Сценарий

```text
/route
Москва -> Санкт-Петербург
выбрать вылет +0/+6/+12/+24/+48 ч
выбрать 150/300/450/600 км/ч
выбрать Простой или Профи
```

### Пространственная дискретизация

- целевой шаг вдоль маршрута — 25 км;
- точки строятся по дуге большого круга;
- ETA каждой точки равен `расстояние / средняя скорость`;
- срок GFS равен `lead вылета + ETA` и приводится к доступному сроку модели;
- скорость изменяет ETA и срок, но не геометрию точек;
- до 161 точки: шаг до 25 км сохраняется для маршрутов примерно до 4000 км;
- на более длинных маршрутах фактический шаг увеличивается и показывается в сводке;
- каждая точка привязывается к ближайшему узлу GFS 0.25°.

Для маршрута Москва–Новосибирск используется более 100 расчётных точек, а не 10–25 крупных интервалов.

### Объективный контракт риска

Риск рассчитывается один раз и не зависит от `mode`.

Для одинаковых run, маршрута, скорости и срока вылета `simple` и `pro` обязаны использовать идентичные:

```text
точки маршрута
GFS-сроки
point_risk
icing_score
turbulence_score
cloud_mask
гроза/осадки
видимость и ВНГО
границы карточек
категории риска карточек
```

Оба режима используют один лимит — до 12 одинаковых по границам карточек. Категория риска карточки равна максимальному риску исходных точек внутри неё.

### Простой режим

`simple` меняет только представление:

- четыре ключевых уровня по вертикали;
- повторяющиеся `☁` внутри облачных зон;
- повторяющиеся `❄` внутри зон обледенения;
- повторяющиеся `≈` внутри зон болтанки;
- подписи `❄ ЛЁД`, `≈ БОЛТ.`, `➤ N м/с`;
- значки грозы и осадков;
- короткие карточки со статусом, символами, сроком и UTC-временем.

В простом режиме нет ветровых барб, RH-контуров и изотерм.

### Профессиональный режим

`pro` показывает те же риски, но добавляет:

- ветровые барбы;
- контуры V20/V30/V40 м/с;
- красные изотермы 0/-10/-20 °C;
- RH 80/90%;
- цветной разреженный орнамент обледенения и болтанки;
- `Vmax`, осадки, минимальную видимость и ВНГО в карточках.

Подробно:

```text
docs/ROUTE_PROFILE.md
docs/ROUTE_PROFILE_VISUAL_REQUIREMENTS.md
```

## Карта `/map`

`mode=gif` при наличии `ffmpeg` создаёт silent H.264/MP4 и отправляет Telegram animation. GIF используется только как fallback.

Каждый кадр содержит:

- дату UTC;
- срок `+ч`;
- номер кадра;
- progress-bar.

## Admin

Настройки `.env`:

```text
TELEGRAM_ADMIN_IDS=123456789,987654321
TELEGRAM_ADMIN_DB=.cache_gfs/admin_stats.sqlite3
```

Команды:

```text
/admin
/admin stats 30
/admin recent 20
/admin users
/admin find @username
/admin add @username
/admin add 123456789
/admin report requests 30
/admin report users
```

Telegram Bot API не предоставляет глобальный поиск пользователей. `/admin find` работает только по локально известным пользователям.

## Установка

```bash
bash install_telegram_bot.sh
```

Ручной запуск:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.telegram.example .env
set -a && source .env && set +a
python telegram_bot.py
```

## Обновление после git pull

`git pull` не обновляет установленную копию в `/opt/gfs_profile`.

```bash
git checkout telegram-bot
git pull
bash deploy_telegram_bot.sh --yes
```

Проверка:

```bash
python runtime_check.py
python -m unittest discover -s tests
bash deploy_telegram_bot.sh --status
sudo systemctl status gfs-profile-bot.service
sudo journalctl -u gfs-profile-bot.service -n 100 --no-pager
```

## Важно

Маршрутный продукт не определяет юридическую или фактическую возможность полёта. Красная категория означает высокий модельный риск, а не закрытое воздушное пространство. Перед полётом обязательны актуальные METAR/TAF/SIGMET/GAMET, NOTAM, данные диспетчерских и решение командира.
