# 🤖 Telegram-бот GFS

Бот строит модельные вертикальные, временные и картографические продукты GFS 0.25° по городу, координатам или Telegram-геолокации.

Это модельная сетка GFS, не радиозонд, не метеостанция и не наблюдение.

## Основные команды

```text
/start      старт и геолокация
/help       инструкция
/cancel     сброс выбора
/cycle      последний опубликованный анализ GFS
/status     доступность сроков и состояние кэша
/profile    вертикальный профиль по точке
/route      вертикальный профиль по маршруту
/aero       аэрологическая диаграмма
/skewt      быстрая Skew-T
/windgram   срок × уровень
/cloudgram  облачность, осадки, грозы
/map        карта, серия PNG или MP4-анимация
/admin      статистика и отчёты
```

Примеры:

```text
/profile Москва +24
/route Москва -> Санкт-Петербург +24 speed=300 step=50 mode=pro
/route Москва -> Новосибирск +6 speed=300 step=25 mode=simple
/map Москва from=0 to=24 step=3 mode=gif
```

## Progress

Для долгих операций бот обновляет одно статусное сообщение. Для `/route` дополнительно показываются номер точки, расстояние, ETA, выбранная сетка и общее число точек.

## Маршрутный профиль `/route`

### Сценарий

```text
/route
Москва -> Санкт-Петербург
выбрать вылет +0/+6/+12/+24/+48 ч
выбрать 150/300/450/600 км/ч
выбрать сетку 25/50/100 км
выбрать Простой или Профи
```

### Расчёт

- маршрут строится по дуге большого круга;
- ETA = расстояние / средняя скорость;
- срок GFS = `lead вылета + ETA`;
- `step` изменяет число пространственных точек;
- каждая точка привязывается к ближайшему узлу GFS;
- эксплуатационный лимит — 161 точка.

При 60 и более точках бот предупреждает о времени расчёта и предлагает 25/50/100 км.

### Объективный риск

Для одинакового запроса `simple` и `pro` используют одинаковые:

```text
точки и сроки
T / RH / U / V / HGT
point_risk
icing_score
turbulence_score
cloud_mask
гроза / осадки / VIS / ВНГО
границы и категории карточек
```

Сглаживание применяется только к display-сетке PNG. CSV и risk engine используют исходные расчётные точки.

### Простой режим

`simple` предназначен для быстрого чтения:

- плотная display-сетка;
- PCHIP и более сильное Gaussian smoothing;
- непрерывный температурный градиент;
- мягкие облачные массы с векторными облаками;
- плавные зоны льда и болтанки;
- векторные пиктограммы ветра, грозы и осадков;
- округлённые карточки;
- четыре ключевых уровня;
- без барб и RH80/90.

### Профессиональный режим

`pro` предназначен для специалиста:

- минимальное display-сглаживание;
- слабый температурный фон;
- CLD / CLD dense;
- ICE1/ICE2+ и TURB1/TURB2+;
- редкая цветная штриховка;
- красные изотермы 0/-10/-20 °C;
- RH80/90;
- V20/V30/V40;
- барбы на исходных точках GFS;
- TSRA/RA;
- числовые карточки R0–R3, Vmax, P, VIS, ВНГО.

Декоративные облака и повторяющиеся крупные иконки в `pro` не используются.

### Файлы результата

Бот отправляет:

1. Telegram-сводку;
2. PNG выбранного режима;
3. CSV исходных точек и уровней;
4. команду повтора с run, скоростью, сеткой и режимом.

Подробно:

```text
docs/ROUTE_PROFILE.md
docs/ROUTE_PROFILE_RENDERING.md
docs/ROUTE_PROFILE_VISUAL_REQUIREMENTS.md
docs/ROUTE_RISK_CONTRACT.md
```

## Геокодирование

Основной провайдер — DaData Suggestions. Локальный словарь и Nominatim используются как fallback согласно `GEOCODER_PROVIDERS`.

## Карта `/map`

`mode=gif` при наличии `ffmpeg` создаёт silent H.264/MP4 и отправляет Telegram animation. GIF используется как fallback.

## Admin

```text
TELEGRAM_ADMIN_IDS=123456789,987654321
TELEGRAM_ADMIN_DB=.cache_gfs/admin_stats.sqlite3
```

## Установка и обновление

```bash
bash install_telegram_bot.sh
```

После `git pull`:

```bash
git checkout telegram-bot
git pull
python -m unittest discover -s tests
python runtime_check.py
bash deploy_telegram_bot.sh --yes
bash deploy_telegram_bot.sh --status
sudo systemctl status gfs-profile-bot.service
sudo journalctl -u gfs-profile-bot.service -n 100 --no-pager
```

## Важно

Сглаженный PNG не повышает физическое разрешение GFS. Маршрутный продукт не является разрешением на полёт. Обязательны актуальные METAR/TAF/SIGMET/GAMET, NOTAM, данные диспетчерских и решение командира.
